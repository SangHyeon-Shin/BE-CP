# 바로 쓰는 프롬프트

출처: Architecture AI Starter Kit(Notion, archaiflow 작성자)과 Revit × Claude 무료 핸드북. 한국 업무에 맞게 옮겼다.

## 핵심 개념(키트 요약)

| 개념 | 내용 |
|---|---|
| AI가 맡을 일 | 법규 조사, 메일·회의록 속 결정사항 정리, 도면·모델 점검, 프로젝트 문서 검색, 반복 문서 작성 |
| 연결 방법 3가지 | ① 파일 첨부(일회성) ② 클라우드 커넥터(Notion, Gmail, Drive, 캘린더) ③ 로컬 MCP(Revit·Rhino·Archicad·CAD 같은 데스크톱 프로그램) |
| 챗봇의 한계 → 에이전트 | 잊는다 → `CLAUDE.md`로 기억 / 기다린다 → 예약 실행 / 답만 한다 → MCP로 직접 실행 |
| 문서 검색(RAG) | PDF → 조각 → 임베딩 → 벡터 DB → 관련 조문 → 답변. 최종 판단은 사람이 한다. |
| 사용 태도 | 빠르지만 가끔 틀리는 동료로 대한다. 틀려도 눈에 보이는 일을 맡기고, 결과는 매번 확인한다. |

프로젝트 폴더용 맥락 파일 견본은 `templates/project/AGENTS.md`에 있다. Codex는 `AGENTS.md`를 읽는다. Claude Code를 쓰는 폴더에는 같은 내용을 `CLAUDE.md`로 저장하거나, `CLAUDE.md` 첫 줄에 `@AGENTS.md`를 쓴다.

## 1. 법규 질의

```
프로젝트 폴더와 적용 법규를 참고해. 법규는 [건축법 / 해당 시 건축조례 / 건축물의 에너지절약설계기준]을 쓰고,
korean-law 도구나 /codes 폴더의 원문에서 찾아.
대지는 [주소], 용도는 [예: 지상 4층 공동주택]이야.
[필요한 것, 예: 주차대수 / 건폐율 / 외벽 열관류율 기준(중부2)]의 정확한 기준을 찾아서
조문 번호, 원문 인용, 법령명과 시행일을 같이 알려줘.
```

## 2. 도면·모델 점검(발행 전)

DXF·PDF 도면:
```
/drawings 의 [도면 파일]을 발행 전 점검해 줘. 레이어명 규칙 위반, 치수 누락, 닫히지 않은 실 경계,
도면 번호와 목록 불일치를 찾아서 문제 유형별로, 심각한 순서로 정리하고 위치(도면 번호·좌표)를 적어 줘.
```

Revit 연결 시(PC):
```
Revit 모델에서 발행 전 점검을 해 줘. 명명 규칙 위반, 태그 누락, 남아 있는 CAD 링크, 미해결 경고를 찾아
[범위, 예: 2층 평면 / 전체 모델]을 대상으로 유형별·심각도순으로 정리하고, 요소 ID와 뷰 이름을 적어 줘.
```

## 3. 회의 준비

```
프로젝트 폴더와 최근 프로젝트 메일을 읽고 [회의, 예: 내일 건축주 회의 / 목요일 설비 협의]용 한 쪽 브리프를 써 줘.
보완 요청 처리 현황, 회신을 기다리는 항목, 지난 회의 이후 결정사항, 다음 마감을 넣고 급한 것을 맨 위에 둬.
```

## 4. 법규·해설서 문서 검색 앱(RAG)

`/documents` 폴더에 PDF(에너지절약설계기준, G-SEED 해설서, 조례 등)를 넣고 Claude Code에 붙여넣는다.

```
건축 문서용 간단한 로컬 RAG 앱을 만들어 줘.
- /documents 폴더의 PDF를 읽는다. 문서명, 쪽 번호, 제목, 조·항 번호를 유지한다.
- 의미 단위로 작게 나누고 각 조각을 임베딩해 로컬 벡터 DB에 저장한다.
- 질문하면 가장 관련 있는 조각을 찾아 그 내용만으로 답한다.
- 답마다 출처 문서, 쪽, 조·항을 표시한다. 근거가 없으면 찾지 못했다고 답한다.
- PDF 업로드와 질문용 간단한 화면, 설치 방법, requirements 파일을 포함한다.
- 한국어 문서다. 한국어를 지원하는 임베딩 모델을 쓴다.
로컬 임베딩을 쓰고 답변 생성 단계는 빼 줘.
```

- 마지막 줄을 넣으면 API 키와 별도 비용 없이 관련 조문과 쪽 번호만 돌려준다. 그 결과를 Claude에 붙여넣어 해석을 받는다.
- 이 줄을 빼면 답변 생성에 API 키가 필요하고, 사용량만큼 Claude 구독과 별도로 과금된다.
- 처음에는 내용을 잘 아는 문서 몇 개로 올바른 조문을 찾는지 시험한다.

## 5. Revit 사용 팁(핸드북)

| 팁 | 내용 |
|---|---|
| 미리보기 먼저 | 큰 작업 전에 "시트를 만들기 전에 미리보기부터 보여줘"라고 요청한다. 미리보기는 계획이고 모델이 아니다. |
| Revit 파일마다 Claude 프로젝트 하나 | 이전 대화 내용을 이어서 기억한다. |
| 사본으로 작업 | 공동 작업 파일은 Detach from Central로 연 사본을 쓴다. |
| Claude 창은 하나만 | 두 개를 열면 둘 다 Revit에 닿지 않는다. |
| 응답이 멈추면 | Revit에 확인 대화상자가 숨어 있는지 본다. |
| Autodesk 실험용 도구는 거절 | "Revit MCP Experimental Technical Preview" 사용을 물으면 Decline. 연결된 모든 모델에 접근한다. |
| 스스로 코드를 쓰기 시작하면 중단 | 스킬을 지정해 다시 요청한다. 스킬 없이 쓴 코드는 불필요한 뷰를 남길 수 있다. |
| 되돌리기 | "원래대로 돌려놔"라고 하면 스킬이 만든 뷰·시트를 지운다. |
| 반복 요청은 스킬로 | 같은 요청을 두 번 하게 되면 스킬로 만든다. |
| Pro 요금제 | 스킬을 쓸 때는 Sonnet으로도 결과가 비슷하고 사용량이 적다. |
